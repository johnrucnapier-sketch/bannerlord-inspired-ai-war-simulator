# 衡岳-V1 / HengYue-V1

Codex从零编写的、只读取本国迷雾观察的确定性规则策略，面向冻结v0.2.0。名称是本轮自行选择的系列名，后续正式版本使用衡岳-V2、V3……；C01–C06是本版开发快照，负结果全部保留。

## 策略主张

胜负不是单次战斗的兵力比，而是能够持续送到关键地点的健康兵力。把同一批兵力的护农、出征、补粮、休整和救援放到一套任务优先级里：

1. **生产保护**：最多四支小型警戒队覆盖村庄周边，补粮、受损或发现强敌时回撤；依赖覆盖与驱离保护运输，不主动攻击敌境盗匪。
2. **机动集中**：先在共同点集结，独立领主队同步移动，避免正式军团的速度代价；尚未到齐的远军不无限拖住一个已具备条件的任务。
3. **解围时机**：从可见围城信息估计城市还能撑多久、援军最早何时触敌、触敌前敌军可能受多少损耗。第一支外援接敌后攻城暂停，不继续虚构城防伤害。已承诺的援军持续执行，不在每次决策被拉回集合点。
4. **机会选择**：集中兵力截击有利的可见敌军与运输队；攻城同时核算城防消耗及可能外援。攻城不合算时可劫掠目标城村庄，压低其后续产出；不按对手名称切换特制逻辑。
5. **可恢复性**：补给城必须有实际粮食；用本轮库存预算分配补粮与调兵，战后把伤兵和整补需求送回可用城市。尚未接战的进攻每六小时重评，已经交战则接受冻结规则中的不可撤退约束。

借鉴了已公开策略中“同步独立纵队”和“保护/压制生产”的思想。实现为独立源码，不导入、继承或读取A-R3/Grok文件。没有机器学习训练、模型API调用、种子判断、全知World、敌方日志或未来随机数访问。

## 运行

需要Python 3.12以上，无第三方依赖。每行读取JSONL请求，保留request_id，返回commands；与官方工具连接：

```sh
python tools/play.py --blue-command '["python3","strategies/submissions/hengyue/v1/agent.py"]' --red march --seed 1 --timeout 2 --output runs/hengyue-v1-demo
```

在任意目录也可用绝对路径直接执行agent.py，策略本身不读取本机文件。默认参考march、世界规则、观察权限均未更改。公开源快照为e8afaaa59f590dca44474ae82a06e5980d0a93ca；对手为该快照的A-R3、Grok v25/v23及冻结march。

## 验证与边界

最终成绩见配套实验报告；开发种子和正式验证种子分开，所有胜负均保留。正式验证使用原JSONL宿主、每决策2秒、完整1680天、交换蓝红。四对手共享六个新世界种子，共48局，不等于48个独立地图。开发者在检查计划结构时见过种子数值，但这些种子未用于开发模拟，策略也不读取种子；不宣称盲测。

局限：仍主要使用单个集中战役群；没有保证各战区同时防守。路径、战力缓存及视野外敌军只能近似估计。驻军超过400的强制扩编可能超出普通整补预算，断粮兜底仍有限。护农与劫掠等机制尚未逐项消融，不能把总胜率归因于单一动作。首版结果不代表最优策略或对未来版本的保证。
