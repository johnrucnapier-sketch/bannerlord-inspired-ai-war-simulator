# 原版风味基准 v1（vanilla_v1）

第三模式默认对手；双方使用同一份代码与参数。该策略借鉴本地核查的Bannerlord 1.5.6宏观AI结构，以原创Python实现；不是官方AI的完整移植，不保证最优胜率。仅从本方观察和公开静态导航图决策，不读取World、隐藏敌方库存、全知事件或未来随机结果。

## 行为循环

1. **整补与恢复编制**：检查兵力、伤员、食物及实际返城路程；从附近可达友方据点中按粮食、可用驻军、距离、本家关系选择整补点。维持有效返城任务，避免每轮横跳。常规整补目标110人，遵守已有近满驻军扩编规则。家族不足3队时，在有至少60驻军、可供30步兵及粮食的安全据点实际建立30人部队；不凭空补兵。
2. **独立巡防**：准备不足或需要补给则返城；否则巡查本家据点及绑定村庄、追击可见且能处理的近处劫匪/敌军。避免同一轮重复分配多个队追同一个目标；没有敌国专属权重。
3. **目标驱动集结**：先找允许攻打的前线目标，再从附近选合格部队。候选需要健康兵超过编制上限60%（150上限下至少91健康兵）、伤兵不超过20%、剩余粮食足够行军至集结点后仍超过15天。前线价值、村庄数量、距离和预计战力共同决定目标。
4. **留有机动队**：进攻军团与集结任务合计最多使用当前领主队数70%（向下取整），最多同时2个进攻军团/集结任务。救急解围独立于进攻限额，不把驻军或城内民兵计入野战援军。
5. **真实汇合**：指定友方前沿据点，各队实际行军抵达。到达健康兵超过原计划90%可集结；首批到达后72小时降至75%，再逐小时下降1个百分点，首版保底50%。还必须满足目标战力和至少2支部队，实际assemble遵守引擎500距离限制。总召集超240小时、集结点受围/失守或目标不再有效则取消。
6. **攻城与解围**：估计目标守军、民兵及当前可见附近敌方领主队；以模拟器防御倍率计算需求，采用20%准备余量。已形成军团保持目标，兵粮不再足够、目标失效或出征超过336小时则解散恢复。解围先实际会合，有足够到达兵力后才共同攻击；不虚构战中撤退能力。
7. **后勤与骑兵适配**：按据点日耗、前线需求、在途货粮和集结需求安排邻接送粮/取粮，避免重复发送同一批缺口。默认倾向在可用驻军处换取骑兵；仍使用真实库存、相同战力及引擎速度规则。

状态保存在普通命令的vanilla_task/目标/开始时刻等附加字段中，不另用全局可变记忆。策略在3小时决策边界运行，存档续跑和命令重放不要求恢复额外模型状态。所有行动通过现有指令接口接受引擎检查。

## 原版依据与模拟器近似

| 项目 | 核查到的原版结构 | 本基准的对应处理 |
|---|---|---|
| 任务选择 | 据点评分、军事目标评分、任务持续性 | 粮/兵/路程/威胁评分及持续任务 |
| 参团准备 | 规模比例超过60%、受邀粮食超过15天 | 用健康兵/150和实际行程余粮，另加伤兵上限 |
| 集结等待 | 战力比例90%，3天后75%，继续下降 | 用健康兵比例；保底50%及10天总超时是适配 |
| 国家自由兵力 | 招募名额参考全国部队70%、扣除已入团人数 | 进攻军团与集结合计硬上限70%，避免抽空所有独立队 |
| 发起资格 | 家族领导身份、影响力、战争与粮食限制 | 没有英雄/影响力系统，不伪造数值；由统一候选规划模拟 |
| 战斗与散团 | 原版估算强度、食物、凝聚力、无活动等 | 用本引擎战力与粮耗；固定出征期限作为简化 |
| 决策频率 | 独立队常规6小时，军团/特殊状态更快 | 保持公平的3小时周期，不给默认策略额外反应频率 |
| 运粮及骑兵训练 | 与本项目规则不同 | 专门适配50民兵运输和72小时驻军转骑兵 |

110人整补、20%攻城余量、20%伤兵限额、最多2个进攻军团、14天后方粮食保留、21天目标库存等均是透明的首版适配参数，不标成原版准确常数，也没有用对抗胜率搜索这些参数。

源码：aiwar/vanilla_policy.py。原版研究仅用于理解结构，官方程序集及反编译代码未加入仓库。可交叉参考官方[战帆AI说明](https://www.taleworlds.com/en/News/587)及[军团改动](https://www.taleworlds.com/en/News/602)；版本不同，不应拿旧补丁数字覆盖1.5.6核查结果。

## 评测口径

将模式/规则配置、vanilla_v1源码哈希、完整地图三文件哈希、双方策略、种子和阵营同时记录。自对抗检查运转，交换阵营的march对照检查接入；有限验证不构成排名、最优性或长期平衡证明。原版风格策略和地图包均可独立复现，未来策略改进以新版本保存。
